# Earth overlays and progressive detail

How geographic layers (borders, rivers, labels, cities, landmark miniatures) attach to the approved Earth without touching its textures, and how they reveal progressively. See [ART_DIRECTION.md](ART_DIRECTION.md) for the visual intent.

## Architecture

- `src/earth/overlays/levels.js`: the four detail levels and their altitude fade bands. Altitude is in Earth radii above the surface; the default planet view sits at ≈ 2.9 and the closest zoom at 0.2.

  | Level | Key | Fades in between altitude |
  | --- | --- | --- |
  | 1 | `planetary` | none (natural planet only) |
  | 2 | `continental` | 2.15 → 1.55 |
  | 3 | `regional` | 0.95 → 0.65 |
  | 4 | `landmark` | 0.50 → 0.32 |

  A layer may override `fadeIn` (for example, lesser cities fading in later within level 3) but stays on its level.
- `src/earth/overlays/overlay-manager.js`: the registry. A layer is `{ id, level, group: THREE.Object3D, setOpacity(o), fadeIn?, onCamera?(camera, altitude), dispose? }`. Each frame the manager maps altitude to opacity with a smoothstep cross-fade, hides fully transparent groups, and reports whether a redraw is needed (demand rendering keeps working). `setEnabled(id, on)` is for player and dev toggles. `state()` reports the level and per-layer opacity for tests.
- `src/earth/overlays/polyline-layer.js`: the first concrete layer type, geographic polylines in `globe.polylines/1` (int16 lat/lon at 1/180°). One draw call per layer, per-class colour and alpha, depth-tested against the Earth so far-side lines are hidden, drawn above the clouds for legibility, and faded toward the limb.
- Placement uses `geodeticToPosition(lat, lon, heightM)` in the Earth-fixed frame. The Earth never rotates, so overlays need no per-frame transforms.

## Implemented now (proof of the architecture)

| Layer | Level | Data |
| --- | --- | --- |
| `borders` | 2 | Natural Earth 10m admin-0 land boundary lines. Disputed, indefinite, line-of-control and unrecognised segments are drawn fainter |
| `rivers-major` | 2 | Natural Earth 10m rivers, scalerank ≤ 4 (the famous large rivers) |
| `rivers-regional` | 3 | Natural Earth 10m rivers, scalerank 5–7 |

Generated by `python pipeline/earth/earth_pipeline.py overlays`. Output: `public/earth/v1/overlays.json` plus `overlays/*.bin` (≈ 1.1 MB). Provenance is in `assets/earth/MANIFEST.json`. Dev toggles **Borders** and **Rivers** are in the explore panel.

**Border policy:** this uses Natural Earth's default (de facto) worldview, which is provisional. The owner must decide the border/naming policy; Natural Earth also publishes point-of-view variants.

## Planned layer types (not built in this milestone)

- **Labels** (levels 2–3): country, ocean, range, desert and lake names, then cities and capitals. Use SDF text, or a canvas-atlas, on billboards anchored at WGS84 points. Priority-based collision culling in screen space, with the same rule for every place of a category. Sources: Natural Earth (`geography_regions_*`, `populated_places`) and GeoNames for cities.
- **Physical features** (level 2): mountain-range and desert names, perhaps with subtle hachure or tint accents. Relief is already in the terrain normals.
- **Landmark miniatures** (level 4): curated glTF models (Blender-authored, KTX2 textures). A registry of `{ id, lat, lon, headingDeg, scale, category, importance, model }` with instancing for repeated parts, LOD (billboard impostor → low-poly → full), oriented to local up/north, lit by the Earth's sun, and shown in the same fade band for every landmark of equal importance. Agree a Git LFS / external storage policy before adding a model library.
- **Skylines** (level 4): curated per-city miniature groups, using the landmark registry.

## Spoiler protection (owner requirement)

While a mystery is active, the Earth must never point at, highlight, mark, or navigate toward the answer, and must never reveal hidden coordinates. The overlay system enforces this by construction:

1. **The overlay API has no concept of an answer or target.** Visibility depends only on altitude, a layer's curated content, and player/dev toggles.
2. **Uniform rules.** Places of the same category and importance get the same level, fade band, styling and label rules. No per-mystery exceptions, including "hide the answer", which would itself be a clue.
3. **No markers in the `mystery` presentation.** `earthView.navigateTo(..., { mark: true })` is the only way to show a marker. The host may use it only after the answer is revealed.
4. **The development fly-to panel exists only in `explore`.** Gameplay screens must not render it or its readouts.
5. **Every mystery starts from the whole planet** (`resetToPlanetView()`): level 1, no overlays, north up, no markers.
6. The Earth module never receives the answer before reveal. `navigateTo` is called by the education bridge only in `ANSWER_REVEAL`.
