# Earth asset contract (proposal v1)

Status: **approved by the owner on 2026-10-22** (Earth V1, PR #2; decisions in docs/DECISIONS.md, discussion in [issue #1](https://github.com/madema-art/globe/issues/1)). Changes go through a reviewed PR and a DECISIONS.md entry. Every runtime asset is generated by `pipeline/earth/earth_pipeline.py`, so changing the contract means regenerating, not hand-editing.

## 1. Geographic data boundary

| Item | Convention |
| --- | --- |
| Datum / CRS | WGS84, EPSG:4326 geodetic latitude/longitude |
| Units | Decimal degrees. Never radians at module boundaries |
| Latitude | `[-90, 90]`, north positive |
| Longitude | `[-180, 180)`, east positive. Normalise with `normalizeLongitude()`; `180` becomes `-180` |
| Argument order | `(lat, lon)` in Globe APIs. GeoJSON/Natural Earth use `[lon, lat]`; adapters must swap explicitly |
| Heights | Metres. ETOPO 2022 heights are relative to the EGM2008 geoid (≈ mean sea level). Ellipsoidal heights are converted explicitly when needed |
| Distances | Great-circle distance on the IUGG mean sphere R1 = 6 371 008.8 m (`greatCircleDistance`). Accurate to ~0.5%, which is enough for scoring. Swap in a Vincenty/Karney geodesic if survey accuracy is ever needed |

Implementation: `src/geography/coordinates.js`, tested by `tests/geography.test.mjs`.

## 2. Earth-fixed render frame (Three.js)

- Unit length = WGS84 equatorial radius `a` = 6 378 137 m.
- `+X` → (0° N, 0° E), `+Y` → north pole, `+Z` → (0° N, 90° W). Therefore 90° E lies on `−Z`.
- This is ECEF `(X, Y, Z)` mapped to `(x = X, y = Z, z = −Y)`, which is a proper rotation, not a mirror. East runs counter-clockwise when viewed from above the north pole (unit-tested).
- The globe is the WGS84 ellipsoid: radii `(1, b/a, 1)` with `b/a = 1 − 1/298.257223563`.
- `geodeticToPosition(lat, lon, h)` gives exact ellipsoid positions. `positionToGeodetic(x, y, z)` (Bowring) inverts it, sub-millimetre at the surface.
- The Earth mesh is never rotated: the camera orbits the planet, and the sun direction is expressed in the same frame. Overlays (borders, labels, markers) are therefore placed directly with `geodeticToPosition` and need no transform.
- Picking uses an exact ray/ellipsoid intersection (`earthView.pickGeodetic(clientX, clientY)`), independent of mesh tessellation.

## 3. Raster layout (all global textures)

- Equirectangular (plate carrée) on geodetic lat/lon, aspect exactly 2:1.
- Row 0 is the north edge (+90°) and column 0 is the west edge (−180°). Pixel-is-area: the centre of pixel `(i, j)` in a `W×H` raster is `lon = −180 + (i + 0.5)·360/W`, `lat = 90 − (j + 0.5)·180/H`.
- UV in shaders: `u = (lon + 180)/360`, `v = (lat + 90)/180`. The image is decoded flipped, so the north row lands at `v = 1`.
- **Texturing is per fragment** from the Earth-fixed position (`common.glsl`: `geodeticNormal → normalToUv`), not from mesh UVs. This removes pole pinching and makes the textures independent of geometry, so a future terrain mesh or tiles can reuse them unchanged.
- **Antimeridian:** sampling uses `textureGrad` with derivatives from a second parameterisation whose discontinuity lies on the prime meridian, so mip selection never spikes at the seam. Textures use `RepeatWrapping` horizontally, so bilinear filtering wraps across ±180°. Source mosaics are feathered over 64 columns so the left and right edges match. The pipeline's `validate` step checks seam continuity.
- **Poles:** per-fragment latitude is exact. Relief normals fade out within ~4.5° of the poles, where the east/north frame degenerates.

## 4. Runtime asset set (`public/earth/v1/`, schema `globe.earth-assets/1`)

`earth.json` is the runtime manifest. Code reads tiers, file names and decode constants from it, never from hard-coded paths.

| Texture | Channels | Colour space | Format | Tiers (px) |
| --- | --- | --- | --- | --- |
| `day` | RGB true colour (Blue Marble NG, July 2004) | sRGB | WebP lossy q90 | 8192², 4096², 2048² wide × half height |
| `surface` | R = water fraction (Natural Earth 10 m land − lakes); G = east slope; B = north slope | linear (`NoColorSpace`) | WebP lossless (packed data must not be chroma-subsampled) | 4096, 4096, 2048 |
| `atmos` | R = cloud cover (NASA Blue Marble clouds); G = night lights (Black Marble 2016) | linear | JPEG q92 4:4:4 (full-resolution chroma keeps channels independent) | 4096, 4096, 2048 |

Slope encoding (normal-map convention): `e = value·2 − 1`, `slope = sign(e)·e²·slopeMax` (rise/run, east and north components, `slopeMax` = 0.12). The perturbed normal is `normalize(n − (sₑ·east + sₙ·north)·exaggeration)`. The sqrt encoding keeps plains distinguishable without clipping the Himalaya. Sea level is forced to 0 m, so oceans carry no relief. Land and ice-sheet relief come from ETOPO 2022 surface elevation (ice surface, not bedrock).

### Budgets (estimates and measurements)

| Tier | Download | Decoded GPU memory (RGBA8 + mips) | Chosen when |
| --- | --- | --- | --- |
| high | ≈ 11.1 MB | ≈ 256 MB (day 8K ≈ 171 MB) | `maxTextureSize ≥ 8192` and not a small touch device |
| medium | ≈ 9.3 MB | ≈ 128 MB | fallback |
| low | ≈ 2.5 MB | ≈ 32 MB | always loaded first (progressive), then replaced |

Override for testing with `?earth=low|medium|high`. Measured: high-tier GPU estimate reported by the running app = 256 MB. Upgrade path for memory: KTX2/Basis Universal (UASTC/ETC1S) would cut GPU memory 4–8×. It needs the Basis transcoder (WASM) and a build-step decision with Codex.

### Geometry and layers

- Surface: `SphereGeometry(1, 256, 128)` scaled to the ellipsoid (33k vertices). Clouds: shell at +0.0045 a (≈ 29 km, exaggerated for legibility), 192×96. Atmosphere: shell at +0.028 a, 96×48, back faces, additive.
- 3 draw calls for the planet (+2 when the target marker is visible).
- Rendering order: surface → clouds (alpha) → atmosphere (additive, preserves destination alpha) → marker.

## 5. Separation of concerns (handoff contract)

- **Physical Earth** (this contract): `src/earth/*`, `src/shaders/earth/*`, `public/earth/v1/*`. It knows nothing of borders, names or questions.
- **Geography data**: `src/geography/coordinates.js` plus compact JSON in `assets/data/processed/` (e.g. `earth-landmarks.json`, schema `globe.landmarks/1`: `{id, name, kind, country, lat, lon, source}`).
- **Overlays** (future: political borders, labels, rivers, educational layers) attach to `earthView` as separate `THREE.Object3D`s positioned with `geodeticToPosition`. They are not baked into Earth textures, so they can be switched, localised and reviewed independently. Natural Earth vectors are already in the pipeline's raw sources.
- **Game** consumes only `flyTo(lat, lon)`, `pickGeodetic(x, y)`, `state()` and `greatCircleDistance()`.

## 6. Validation sample

`python pipeline/earth/earth_pipeline.py validate` checks:
- 19 landmarks: GeoNames cities on every continent, including Suva (near the antimeridian), Quito (equator), Nuuk and Reykjavík (high north), Ushuaia (far south), plus the Natural Earth Madagascar centroid. Each must fall on land in the water mask.
- 7 open-ocean points must be water: mid-Atlantic, central Pacific, the antimeridian, Southern Ocean, Arctic, Mozambique Channel, Indian Ocean.
- Left/right edges of every raster must be continuous.

`tests/geography.test.mjs` checks the axis convention, shader-UV equivalence, ellipsoid round trips, longitude wrapping, distances, the subsolar point and manifest consistency. `tests/earth-browser.mjs` flies to Antananarivo and picks the centre pixel back to its coordinates.

## 7. Future upgrades this contract allows

- **Sharper imagery:** rerun the pipeline with larger `TIERS` (Blue Marble is 21600×10800 at source), or add regional patches as extra equirectangular windows `{bounds: [west, south, east, north], url}`. The shader would blend them with the same UV convention.
- **Terrain tiles:** replace the sphere geometry with displaced patches (Copernicus GLO-30 / ETOPO 15″) while keeping per-fragment texturing. Heights in metres follow §1.
- **Zoom-dependent detail:** a tier per altitude band, or tiles, chosen by `controls.altitude`.
- **Borders, labels, rivers:** Natural Earth / GeoNames vector overlays (§5).
